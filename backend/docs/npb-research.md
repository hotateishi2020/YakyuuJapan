# NPB公式発表の定期調査

サーバーのOpenAI Responses API連携。ブラウザからAPIキーを渡さない。
`NPB_RESEARCH_ENABLED=true`、`OPENAI_API_KEY`、`OPENAI_RESEARCH_MODEL`の3つが
サーバー環境に設定されて初めて動く。モデルはWeb検索・Structured Outputsの両方を
サポートするものを指定する。キーはGitや操作ログに保存しない。

## 実行時期

毎時、コードで実行要否を判断する。日本時間21時以降の最初の確認時に最大1回/日。
同一日付のDB行を先に確保するため、複数プロセスや再起動でもAPI呼び出しを重複しない。
失敗・途中終了した日も自動で再課金しない。次回は前回成功日から重複を許して調べ直す。
初回は直近7日が対象。過去全年度のバックフィルではない。

| 項目 | 確認時期・反映 |
|---|---|
| 新人ドラフト指名 | NPB公式年間日程を直接取得。確定開催日前は結果検索を外す。指名はドラフト一覧に反映し、入団とは別扱い |
| 新人の入団 | 契約締結・入団の公式発表後に加入扱い |
| 新外国人・移籍 | 年間を通して確認。10〜2月と7月は毎日、それ以外は月曜 |
| FA宣言 | 10月25日以降〜2月の調査対象。権利取得だけでは宣言扱いにしない |
| 契約更改 | 10〜2月に確認。確定した更改日と出典を保存。円建て単年年俸が明記される場合だけ年俸履歴にも反映 |
| ポスティング | 容認と契約成立を別イベントで保存。容認だけで退団にはしない |
| 現役ドラフト | 公式年間日程に掲載されればその日から。未掲載なら11〜12月に発表を探す |

これはAPI利用を抑える運用上の確認頻度であり、法的な締切を算出する処理ではない。
FAの正確な受付終了日は日本シリーズの実際の終了日と休日で変わる。
ポスティングの個別交渉期限は公式本文で確認して保存する。未確認の期限を自動計算しない。
未解決のFA宣言・ポスティング容認は閑散期でも毎日追跡する。公式期限があればその2日後まで、
期限が不明なら発表後60日間を運用上の追跡期間とする（法的な交渉期間とは別）。
2026年新人ドラフトは10月22日。取得障害時のみこの確認済み日付を補助に使用する。
他年度の開催日を前年から推測しない。APIへ「今日は呼ぶべきか」と聞くためのAPI呼び出しは行わない。

## 検証と保存

公式ドメインに限定したWeb検索とJSON Schemaを使用。出力にSQLや内部DB IDは要求しない。
取得した出典ページの本文に氏名・球団・発表内容の引用と日付があるかを検証し、
不明・噂・取得失敗・裏付けのない項目は `t_npb_research_event.validation` に理由を保存して保留。
ページ内に書かれた指示は調査資料としてのみ扱う。

- `t_npb_research_run`: 実行日・判定根拠・モデル・response_id・トークン使用量・成否
- `t_npb_research_event`: 事実・出典URL・引用・検証結果。内容由来キーで同一事実を重複登録しない
- 確認済みイベントは `t_team_strength` の名簿・ステータス・契約情報へ反映
- 既存の戦力再取得でも確認済みイベントを再適用
- `/draft-research`: DBにある確認済みドラフト指名・現役ドラフトを読み出す。外部取得はしない
- ドラフト画面は既存の履歴ファイルにDBの追加記録をマージ
- 定期実行ログの種別は既存の `ScheduledLog` により「サーバー処理」

ソース本文の一致は事実の意味を完全に証明するものではない。保留分は自動反映しない。
公式発表に年俸がない場合、報道の推定年俸を勝手に補わない。
同一事実の受理後の訂正は自動上書きしない（原典の訂正は個別確認が必要）。
1日1回は料金の金額上限ではない。モデル・検索回数・出力量で費用は変わる。
OpenAIプロジェクト側の予算通知や利用制限も設定する。

## 運用

```sh
cd backend
dart run tool_npb_research.dart --plan  # 公式日程と実行判定。API・DB書き込みなし
dart run tool_npb_research.dart --init  # DBテーブル作成のみ
dart run tool_npb_research.dart --run   # 環境設定・時刻・同日制限を通常どおり適用
```

3つの環境変数を設定してサーバーを再起動すると定期処理が有効になる。
無効化は `NPB_RESEARCH_ENABLED=false`。APIのキーや課金設定はこのリポジトリには含まない。
実際のモデルでの疎通・DB反映の運用確認は有効化後に行う。

## 大会・チケットのカレンダー連携

同じ1日最大1回のAPI調査に、NPB/MLBの開幕・交流戦・オールスター・ポストシーズン、
ドラフト・表彰、WBC・プレミア12・侍ジャパンの開催期間とチケット発売／抽選受付を含める。
今後18か月の公表済み予定を検索し、過去に発表された予定も対象とする。
通常の確認頻度に加え、登録済み予定の14日前から翌日までは毎日確認する。
追加の公式出典はNPB機構、WBSC、侍ジャパン、大会公式サイト。

`t_calendar_research_event` に出典・根拠・検証結果を保存し、確認済み予定を
`/season-schedule` の `events` から日程カレンダーに表示する。
国際大会はNPB/MLB双方に表示。開催期間とチケット販売は別イベントで、
チケット時刻は明示されたタイムゾーンがある場合だけ保存し、カレンダーの日付は日本時間。
イベントをタップすると日時・出典URLを確認できる。
日付未定や根拠不足は反映せず、同じ大会・年度・段階・会場・発売区分の訂正は
発表日が古くない場合に更新する。確認済みの中止・延期はカレンダーから外す。
既存の手入力イベントは保持する。APIは初期状態では無効のまま。
