# 画面用の事前集計

`/season-schedule` と `/records` は `t_page_snapshot` の保存済みJSONだけをSELECTします。`/records?section=titles` と `section=timeline` は必要な項目だけを返し、連続記録などの大きなデータを転送しません。年表から別の記録タブへ移ると必要な全体データを取得します。

- 日程・チーム順位：5分ごと（順位は元データ取得完了時にも更新）。
- タイトル・年表：30分ごと。過年度のページは1日ごと。
- 選手詳細：1時間ごと。再起動2分後に不足・期限切れを補完。ID指定で開かれた未登録選手は5分ごとの補完対象にも追加。
- 過年度の日程・記録：DBに存在する年度を新しい順に事前作成。1巡に最大6ページでDB負荷を制限。未登録ページの要求は次の巡回で優先する。

更新はサーバーのタイマーで行います。サーバー停止中は動作しません。再起動後も保存済みデータは残ります。集計が失敗しても前回のJSONを維持し、成功時に1回のupsertで置換します。同じページの同時更新はDBのアドバイザリロックで防ぎます。初回未集計は `pending: true` を返し、画面に準備中と再読み込みボタンを表示します。

選手の成績は保存済み詳細を読みます。画像だけは従来どおり登録済み画像を別途参照し、現在の所属・背番号との整合性を確認します。外部画像生成や成績集計は表示要求内では行いません。

初回作成（backendディレクトリ）:

```sh
dart run tool_refresh_page_snapshots.dart 2026
```

読み取り計測:

```sh
dart run tool_verify_page_snapshots.dart
```

集計処理は元データ取得の代わりではありません。元データの更新時刻に加え、レスポンスの `updated_at` が事前集計時刻になります。定期処理の成功・失敗は `page_schedule_npb` 等と `standings_snapshot` のシステムログに記録します。
