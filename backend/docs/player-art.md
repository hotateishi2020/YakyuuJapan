# 選手キャラクター画像

ユーザー指定の原文は `prompts/player-character-v1.md` に保存。毎回この本文と選手ごとの確認資料から生成する。個別ポップアップ用には1リクエスト1選手の縦長パネルを作成する。

追加指定として、既存の漫画・アニメ・ゲームのキャラクターの再現は禁止。フィギュアや表紙内の絵も対象とし、確認済みの好きな作品はキャラクター絵のない背表紙や通常書体のタイトル文字で控えめに表現する。自動画像検査にも同じ条件を適用する。生成済み画像の個別メタデータには実際に使用した当時のプロンプトを保持する。

## 自動更新

題材は確認済み情報をカテゴリに分け、出身地・特技・逸話・経歴・功績などから原則3〜4カテゴリをランダムに組み合わせる。出身地の背景は維持し、好きな作品・食べ物は合計で原則1題材まで。資料が不足する場合は創作せず題材を減らす。

犬・猫などの動物は単なる飾りとして配置しない。本人のペットや具体的な逸話など、本人との関係を確認できる場合だけ採用し、自動画像検査でも根拠のない動物を不合格にする。

選手は帽子・ヘルメットを着用せず、本人の確認資料に基づいた髪型・髪色を見せる。頭部が隠れた写真しかない場合は追加資料を確認する。この条件は生成プロンプトと自動画像検査の両方に適用する。

`PlayerArtSchedule` は1時間ごとに所属・背番号・引退/削除状態とプロンプト版を確認し、変更された現役選手と新規選手を生成待ちに登録する。初回は既存選手の基準だけ作り、一斉課金しない。名簿に古い所属情報が残る場合も、基準作成後の変更だけを画像の再生成・無効化に使う。目視確認済み画像の再登録はプロフィールと検証情報も更新する。NPBは公式選手ID付きの球団名簿（t_team_strength、ドラフト/移籍調査の反映先）も監視するため、選手マスター未登録の加入選手も検知できる。公式IDの確定後、背番号が名簿に無い場合は公式プロフィールを調査して確認してから生成する。未取得の背番号だけでは既存画像を無効化しない。MLBおよび名簿未取得球団は選手マスターの変更を検知する。未契約・移籍先未定のニュースだけでユニフォームを推測しない。

サーバー環境変数:

- `PLAYER_ART_ENABLED=true`
- `OPENAI_API_KEY`（サーバーだけに設定）
- `PLAYER_ART_RESEARCH_MODEL`（Web検索・画像入力・構造化出力対応モデル）
- `PLAYER_ART_IMAGE_MODEL`（既定 `gpt-image-2.5-sunburst`）
- `PLAYER_ART_BATCH_SIZE`（1回3人、最大20）
- `PLAYER_ART_DIR`（永続保存先。既定 `data/player-art`）

Responses APIのWeb検索でWikipedia日本語版・公式・報道を調査。根拠ページの短い引用が本文に存在することを検証し、氏名の英語表記・所属・背番号・出身地・外見を確認できない場合は保留する。公式の本人写真を参照画像としてImages APIで生成後、画像入力対応モデルで文字・背番号・鼻口・投打の左右・出身地と小物の整合性を検査する。検査失敗や通信中断は `needs_review` にし、有料生成を無制限に繰り返さない。元画像と資料は保持する。

`dart run tool_player_art.dart baseline` で既存名簿の監視基準だけを作成。`sync` は新規・変更選手をキュー登録。`run` で待機中の画像を処理。`register-reviewed` は初回マニフェストの `reviewed=true` の画像だけを登録する。`register-official <metadata.json> <image.png>` は公式ID付きの個別画像を登録する。旧選手マスター用の `register` は `player_ids, id_team, number, research, prompt` 形式を使う。

初回の球団公式名鑑118人は `t_player_art_official` に公式選手IDで登録する。マスターに未登録の選手も公式プロフィールと画像を表示できる。生成条件・出典は `data/player-art-initial/*.json`、生成画像は同ディレクトリに保存し、確認後に配信用ディレクトリへ登録する。初回は組み込みimage_genを使用。

自動生成のDBは `t_player_art_roster` と `t_player_art`。選手IDと入力フィンガープリントの複合キーで重複を抑止。並列ワーカーは `FOR UPDATE SKIP LOCKED` で仕事を取得する。サーバー処理ログに記録する。

画像は `GET /player-art/<id>-<fingerprint>.png` から配信し、`/player-detail` の `character_image` で参照。既存詳細スナップショットの再集計を待たず表示。所属・背番号が現在のマスターと一致しない画像は表示しない。`PLAYER_ART_DIR` を永続ボリュームに保存し、DBと併せてバックアップする。

公式API仕様: https://developers.openai.com/api/docs/guides/image-generation 、 https://developers.openai.com/api/docs/guides/tools-web-search

初回対象: 2026年10月20日に確認したソフトバンク公式名鑑の118人（育成を含む）。公式写真を参照して組み込み画像生成で作成し、全件を目視確認。市町村が資料で確認できない場合は、確認できた地域の一般的な風景を用いる。
